本次在主目录完成 60 题真实 BGE 检索对比，以及固定 16 题 × 两种策略的 DeepSeek 问答。混合检索在这份小型合成集上表现更好；产品仍默认精确向量，用户可在检索页选择混合方案。结果不能外推为生产准确率。

`evaluation.json` 记录 UTC 时间、数据库版本、操作系统/架构、参数、模型、每次结果与耗时。模型预热不计入单次请求。两条 SQL 分支都保留当前组织、成员、软删、READY、正文hash、索引/模型/切块版本约束；生成前后复查全部召回来源。

RRF 采用排名倒数求和，参考[原始论文](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf)。模型版本和价格依据[DeepSeek 官方价格页](https://api-docs.deepseek.com/quick_start/pricing/)，快照日期2026-11-11；以后复跑应核实价格，不能假设别名永远对应同一模型。

## 指标口径

- Recall@K：每题前K条结果完整覆盖的标注证据区间数 ÷ 该题标注区间总数，然后对52正例取宏平均。单条结果需包含完整区间，跨块拼合不计命中。
- Hit@K：是否至少覆盖一条标注证据。它不是多证据Recall。
- MRR@5：首条相关结果的倒数排名；前5没有命中记0，再对52正例平均。
- 负例拒答率：8道固定负例中返回 `insufficient_evidence=true` 的比例；负例不混入正例召回分母。
- 引用标注相关率：返回引用中完整覆盖任一相关标注区间的比例；引用证据召回率：标注区间被返回引用覆盖的比例。对8道正例问答取宏平均；无引用的正例证据召回记0，相关率为空。**这两个指标不是句子级语义蕴含率。**
- 来源合法性：返回片段的组织、文件、Unicode偏移与实际原文一致；非法引用由适配器/服务端拒绝。合法性与相关性分开。
- 请求错误保留并单列；检索错误在正例召回/MRR分母中计0。耗时仅统计实际有响应的成功请求并同时列错误数。毫秒整数可能截断为0。

## 失败分类与证据

| 类型 | 本次案例 | 含义与后续方向 |
|---|---|---|
| 检索遗漏 | vector：M02、S08、M06、M08；hybrid：M06 | 检索不全会导致多事实问题只能部分回答；应扩充语料/人工复核后再考虑改写或重排 |
| 引用区间不完整 | K06 vector引用从420开始，标注从418开始 | 重叠块截掉错误码开头两个字符，严格区间指标记不相关；回答文字本身仍可能正确，不能直接称幻觉 |
| 多余引用 | K06 hybrid引用包含完整块和截断块 | 相关率0.5但标注证据召回1；后续可以评估按段落切块/重叠去重，不能直接删除现在的失败案例 |
| 不完整回答 | M06两方案只覆盖限流重试，缺模型不可用时其他功能的依据 | 实际返回说明该部分材料不足；不能因有合法引用就宣称问答全部正确 |
| 无答案/跨组织 | N01～N04、X01～X04 | 本次均拒答；8道合成负例不足以证明普遍安全或无幻觉 |
| 模型/解析/超时 | 本次0 | 脚本保留固定错误码与HTTP状态；后端另有故障注入测试，不能混作真实语义结果 |

以上失败分析由 AI 对固定证据进行检查，未经过人工标注复核。未修改标签、重试模型挑选好答案或调整阈值重跑来提高数字。

## 结论与复跑

混合方案在当前样本上增加约3～5ms数据库工作，召回与首位排序更好；但语料只有14块，统计样本小，不能证明在大库或真实工单领域仍然更优。默认保持vector，hybrid提供明确选择和实验对照。是否默认切换，建议等人工复核与更大独立留出集后决定。
