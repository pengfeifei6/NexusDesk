# 项目简历素材与使用边界

下面是基于代码和实验证据整理的素材。项目是个人学习作品，AI 参与了实现、测试和文档；不要直接改成“独立负责企业生产系统”，也不要捏造任职、团队规模、真实客户、DAU、营收或线上 SLA。你亲自复习、复现并能够解释的部分，再以自己的实际职责组织表达。

## 可整理到简历的一版

**NexusDesk｜组织工单与受控 AI 知识工作台｜个人项目（AI 辅助开发）**

Go、Gin、PostgreSQL/pgvector、Redis/Asynq、Vue、TypeScript、RAG、SSE。

- 构建组织隔离的工单协作闭环，提供 39 个业务 API 与 10 个主要页面；身份认证和组织授权分离，工单采用版本检查与事务事件，支持并发领取、评论、指派及软删除。
- 将文档处理拆成 PostgreSQL 持久任务与独立 Worker，采用租约、心跳、执行 token 和有界重试处理重复投递与进程崩溃；知识检索支持精确向量、词项融合和来源复核。
- 为 AI 会话接入 SSE 与有限工具，创建工单必须经用户确认；加入会话 owner 隔离、数据库幂等结果与 Redis 共享配额。
- 使用真实 PG/Redis 的 Go race、前端组件测试和浏览器验收验证链路；通过 profile 定位缓存解码分配热点，并保存性能对比与 Redis/DB/Worker 故障恢复证据。

## 投递前自己完成的两项演示

用自己的话解释“两个用户同时领取为什么只有一个成功”，再解释“Worker 写完索引但确认任务前崩溃如何收敛”。从代码定位事务和条件判断，亲自跑一次受影响测试；不读 AI 答案也能说明失败边界后，再把它们作为面试主线。个人掌握与求职投递不由此次自动交付代完成。
