# NexusDesk 阶段性项目介绍：第五周

2026-11-11，AI按开发者委托结合源码与实际运行记录整理。当前已形成可在本机使用的**组织工单系统 + 私有知识库入库模块**。第一至第五周工程任务已验收；知识库可以管理和提取文档，尚无AI问答。

## 现在能做什么

| 能力 | 网页可操作范围 |
| --- | --- |
| 账号与组织 | 注册、登录、创建首个或后续组织、选择/切换本人组织 |
| 工单 | 建单、分页筛选、详情、领取、状态推进、评论、事件 |
| 知识库 | TXT/MD/PDF上传、列表/状态过滤/分页、详情、下载、删除 |
| 文本处理 | TXT/MD显式解析、状态和错误提示、纯文本预览 |
| 权限 | 服务端按每次请求查active成员；不同组织隔离；删除文档限上传者/admin |

当前24个业务API（身份/组织7、工单10、知识库7），另有健康检查；8张业务表、8条迁移、7个主要页面。注册与创建组织此前只有API，现在已补齐网页入口，新账号可以直接开始使用。

成员查询/添加仍使用API；成员管理页面、工单基础编辑/管理员指派/删除的页面尚未补齐，已有后端接口保留。没有角色修改/停用接口、独立support角色、PDF正文解析、RAG、向量库、Worker、SSE和公开部署。

## 当前怎么运行

本机开发数据库已从6仅追加升级到8。旧Go进程仍需停止后在原已加载配置的终端运行 `go run ./cmd/api`。前端运行 `npm --prefix web run dev`，访问5173；本机Node24路径和新终端配置加载方法见[运行演示](demo/g2-ingestion-demo.md)。

进入页面后：**注册/登录 → 创建或选择组织 → 工单/知识库切换 → 上传 → 点击解析 → 预览/下载**。Token只在内存，刷新后需重新登录。旧API未重启时新路由会404；启动缺JWT_ISSUER等提示表示当前终端尚未加载完整配置。

五个存储变量均有默认值，已有配置无需为本周补必填变量；原有12个必需环境变量继续有效。AI没有读取或修改真实.env，也没有往日常库批量导入测试账号或样例。10份样例的READY结果来自已经清理的隔离测试库。

## 后续怎样维护

1. **小改动先跑相关测试。** Go改动做vet/build，web改动做unit/build/lint/format；涉及SQL、权限、上传或流程再运行 `python3 scripts/week05-smoke.py`。它使用自有可丢弃资源，不回滚日常库。
2. **数据库只追加迁移。** 00001～00008已是历史，不修改它们来改变现有结构；新结构从00009开始。接口/权限变化同时更新契约和用例。
3. **同时保管数据库和原文件。** 默认原文件在被Git忽略的 `var/storage`；软删除只隐藏访问，不立即清磁盘。备份需要两者，cleanup.json需结合数据库引用核对，详见[ADR-0005](decisions/0005-private-object-storage.md)。
4. **按真实版本保存代码。** 当前分支 `feat/week05-knowledge-ingest` 保留未提交的W04和W05工作，AI未commit/push。提交前审查已跟踪差异与新增文件，排除真实.env、私有文档和无关的`--data`/`-H`，不直接盲目git add -A。
5. **工程通过与个人掌握分开。** 本次按委托由AI实现、审查和运行测试；开发者可按[20道回答](weekly/week05-answers.md)逐项复习，独立完成情况仍待本人确认。
