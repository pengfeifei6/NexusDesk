# NexusDesk 第八周阶段介绍

NexusDesk现在是一个本机可运行的组织工单与知识协作系统：用户注册登录、创建组织，进行工单流转；上传文档后由后台Worker完成提取和向量索引；既可以使用普通知识库问答，也可以通过新的AI对话逐段获取回答、读取本组织工单或提出待确认建单建议。

本周新增的是“受控工具调用”。模型不会自动创建工单：先保存提议，页面显示标题、正文、优先级、组织、提出者与有效期，用户确认后才在同一数据库事务中创建工单、审计事件并更新提议。重复确认返回同一工单ID。组织身份与权限始终由后端判定。

现有规模：39个业务API、1个健康检查、14张业务表、12条迁移、9个主页面。后端Go模块化单体；前端Vue3/TypeScript/Pinia；PostgreSQL+pgvector存业务与向量；Redis/Asynq投递异步任务；Ollama/BGE-M3做本地Embedding；DeepSeek负责已配置的文本生成。AI流式适配器同时保留本地Ollama选项。

## 现在可以体验什么

| 页面/能力 | 当前行为 |
|---|---|
| 登录/注册/工作台 | Token仅内存；创建组织和首位admin同事务 |
| 工单列表/详情 | 创建、领取、状态流转、评论、事件记录 |
| 知识库列表/详情 | TXT/MD上传、提取/索引、异步任务状态与重试/取消；PDF仅文件管理 |
| 检索问答 | 本组织向量检索与有真实来源的非流式Ask |
| AI对话 | owner私有会话、流式文字/引用、停止、get_ticket、待确认工单卡片 |

浏览器入口 <http://127.0.0.1:5173>。登录后选组织，点“AI 对话”。启动与例子看 [第八周运行说明](demo/week08-demo.md)；全部测试与实际局限看 [week08](weekly/week08.md)。

## 从main理解新依赖

`cmd/api/main.go`现在先组装TicketService、RAGService，再把它们交给ai.Runner；ai.Store负责会话和提议；ChatService管理生成名额与落库；Handler注册到现有RequireUser保护组。新增模块集中在 `internal/ai`，模型网络协议集中在 `internal/platform/llm/stream.go`。改普通工单规则仍去TicketService，AI路径复用它。

旧的 [main依赖指南（截止第七周）](从main理解项目依赖与修改指南（截止第七周）.md) 保留为历史，新增调用链看 [Agent流程](ai/agent-flow.md)。不要为了修改一个工具直接在Handler或Runner里复制SQL。

## 后续维护重点

修改前先确认分支和未提交差异；数据库结构只追加迁移。改API同步更新DTO、前端、requests和接口文档。权限与确认改动必须运行真实PG隔离测试，go test -race不能替代数据库事务验证。模型提示和参数是高风险输入，不把模型自然语言当作执行事实。

日常维护执行 `python3 scripts/dev.py status` 查看本机依赖，普通改动运行Go和前端检查；涉及数据库、流和工具时运行 `python3 scripts/week08-smoke.py --backend-only`，需要真实模型/浏览器时显式加 `--live`。不要在日常库Down、清空Redis或删除卷来修复启动问题。

尚未宣称完成：公网部署、可靠限流、多人共享AI会话、全量历史分页与归档、断流续传、多实例AI租约、PDF正文处理、成员管理及部分工单编辑功能的完整UI。模型可能漏调工具或文字不准确，应以真实来源与持久化确认卡片为依据。
