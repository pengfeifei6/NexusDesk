## 候选接口

| 读接口 | 查询与变化 | 决定 |
|---|---|---|
| 工单列表 | 按组织、状态、优先级分页；常刷新 | 缓存，覆盖创建/领取/修改/状态/删除/AI 确认 |
| 知识文档列表 | 按组织、处理状态分页；异步处理会更新 | 缓存，覆盖上传/处理/失败/Worker/删除 |
| 工单详情 | 工具和人都可能立即据此决策 | 直接查库，避免扩展状态语义 |
| 组织/成员列表 | 权限关系变化具有安全含义 | 本周不缓存，成员授权始终实时 |
| AI 历史与待审批动作 | owner 隔离、持续追加、决策状态敏感 | 本周不缓存 |
| 知识正文/下载/RAG 来源 | 私有文件/大文本和来源有效性 | 本周不缓存 |

SQL 实验只用随机独立 Compose 项目。tickets 和 knowledge_documents 各 120,000 行；组织分布 100,000/10,000/10,000；每三个相邻条目同 created_at；每 17 行一条软删。工单每 101 行一条高优先级，文档每 1009 行一条 READY。这是明确偏斜的合成读负载，不代表生产数据比例。详情见可重跑的 `scripts/week09-performance.py`。

原来已有 `(org_id,created_at,id)` 和 `(org_id,status,created_at,id)` 部分索引，因此不重复添加。原工单高优先级第一页需丢弃约 1891 行，原知识查询的 generic plan 需丢弃约 19076 行。原始 JSON 计划和九次测量保存在 `docs/testing/evidence/week09/sql-plans.json`。
