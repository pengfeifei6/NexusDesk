# NexusDesk 第六周阶段介绍

截至2026-11-11，本项目已从组织工单与私有知识库，扩展为可运行的**组织内检索与带来源问答原型**。技术链路使用Go模块化单体、Vue3、PostgreSQL17/pgvector、本地Ollama模型，已完成真实数据库、真实模型和浏览器验收；还不属于经过公网部署和生产规模验证的产品。

当前共28个业务API、1个健康检查、10张业务表、10条迁移、8个主要页面。第六周新增4个API和1个检索问答页，知识库详情增加索引操作。完整路径为注册→创建组织→创建/领取/推进工单；以及上传TXT/MD→提取正文→建立索引→检索→问答→点击来源核验。

| 模块 | 后端 | 前端 |
| --- | --- | --- |

第六周功能已前后端匹配，前几周遗留的成员管理和工单编辑/指派/删除页面没有被本周顺带实现。PDF提取、support角色、修改/停用成员接口、异步Worker、SSE、工具调用、公开部署与可靠防暴力破解仍待后续。

检索采用固定500/80字符窗口、1024维BGE-M3、组织与版本过滤后的精确余弦排序。生成使用本地Qwen3.5:35b，没有跨组织工具权限。有效引用来自数据库片段，生成前后复查权限与全部召回来源；无依据时明确拒答。业务权限不依赖前端隐藏按钮或模型提示词。

20题固定真实语义评测：有答案题Hit@5为100%，MRR0.865；多证据题覆盖率83.3%，无答案Search空集率仅25%，生成层4/4拒答。说明基线可用，也说明召回还需要优化。语料/参考证据由AI预标注，人工复核未完成，不把这些数字写成真实生产准确率。

维护时优先保持旧迁移不可变、追加新迁移；功能变化同时更新API/权限/测试；使用隔离烟测而非回滚日常库；备份数据库和私有文件需分别考虑。索引可以重建，原文件和正文仍应按私有数据保管。当前日常库已从8只Up到10，重新创建容器必须带pgvector overlay。
