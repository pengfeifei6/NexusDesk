## Security and meaningful coverage

- The generator keeps fixed system instructions separate from JSON query/name/excerpt data, supplies no tools, validates structured output and canonical citation IDs, and checks IDs against the sources actually retained after prompt budgeting. The service constructs returned sources from retrieved rows and deduplicates IDs. Tests exercise malicious-looking input boundaries, dropped-source citations, malformed responses, nonexistent IDs, missing citations, and no-evidence refusal without invoking generation.
- The real B sample includes an injection attempt and records the expected seven-minute answer with unchanged ticket results. That is a useful bounded observation, not proof of resistance to arbitrary prompt injection. The source also explicitly labels its attack text as test data. Authorization and absence of execution tools provide stronger enforceable boundaries than prompt wording alone.
- Real database Ask tests pause generation using channels, then delete or replace cited and uncited sources, change an uncited index version, or revoke membership. They assert failure and no returned answer/source content. Search separately tests revoked membership during embedding and excludes foreign, deleted, failed, stale-hash, and stale-version rows. The implementation revalidates all retrieved sources, including uncited or budget-dropped evidence.
- Vector validation covers count, dimension, finite values, and nonzero norm before persistence/search; extreme finite vectors are normalized using float64 accumulation. Adapter malformed/null/overflow tests and real database invalid-vector tests complement each other. The real SQL test checks cosine scores, ordering/ties, threshold, top-k, source metadata, and an actual EXPLAIN; synthetic coordinates are not presented as semantic quality.
- Index tests verify exact rune slices, reuse without another model call, retries/version increments, and failure status. Channel barriers plus `FOR UPDATE NOWAIT` verify that model work does not retain claim locks. A trigger fails the second replacement insert and the test confirms the fault was reached, original rows survived rollback, and FAILED indexes hide those retained rows. These tests exercise consequences rather than merely mirror helper implementations.
- The resolved database-budget tests distinguish the local three/five-second bounds from longer caller deadlines. Cleanup-context tests cover a live bounded independent rollback context. Network-stalled rollback and process-crash recovery are not empirically injected here; abandoned INDEXING recovery remains an explicit later-week limitation.
- Expected error paths return fixed public codes/messages and do not log raw model bodies, prompts, queries, or SQL errors. Adapter and handler tests check hostile error text does not escape. The recorded model-outage log includes enabled/disabled RAG checks with old identity/ticket/knowledge routes still usable and query/credential log sentinels absent. Sentinel checks and static absence of logging do not certify every possible panic or arbitrary secret pattern.
