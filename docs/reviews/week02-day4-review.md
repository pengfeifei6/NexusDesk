## 1. 发现与处置

| 编号 | 触发与影响 | 修正 | 验证 |
| --- | --- | --- | --- |
| W02-D4-R01 / P2 | 默认 NumericDate 按秒截断；未来半秒的 iat/nbf 或超长半秒的 exp 可以变成允许值，字符串/空 nbf 也可能被宽松接受 | 自定义 Claims 解码先对 iat/exp/nbf 的原始 JSON 做 int64 整数检查；拒绝小数、指数、字符串、null 与溢出，然后使用既有签名/时间校验；不改全局精度 | 新增未来半秒、超长半秒、null/字符串红灯及溢出/指数回归，修复后通过 |
| W02-D4-R02 / P2 | 256 字节标签可因 JSON HTML/控制字符转义扩张，合法配置签发的 Token 可能超过原 4096 解析上限，登录成功后却无法验证 | 保留 256 字节标签合同，解析预算增至 8 KiB以覆盖当前字段最坏转义，并在签发端增加长度防线 | 最大 int64 用户与最坏标签均可自验证；超长但签名正确的 Claims 仍拒绝 |

审查方建议第二项可用构造阶段的精确长度预算拒绝配置；主代理采用固定 8 KiB 预算以保留所有已允许的 256 字节标签。这个选择把解析最大输入增大一倍，仍有限且不影响算法/签名检查；未来扩展 Claims 必须重新检查输出预算。
