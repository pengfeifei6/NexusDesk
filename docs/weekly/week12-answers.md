# 第十二周常见问题与回答

## 1. 现在算开发完成了吗？

十二周目标的本地求职 MVP 已实现并完成回归，包括当前 39 个业务接口对应的工作台和交付材料。完整不等于未来功能无限扩展：PDF 提取、角色修改、SSO、公网部署、高可用等列在[边界矩阵](../release/acceptance.md)，不声称已经完成。

## 2. 为什么之前有接口但没看到按钮？

早期周次优先完成后端，成员添加及工单 PATCH/DELETE 的完整 UI 未纳入当时范围。W12 已补齐“组织成员”、编辑、指派/解除和删除确认。按钮仍受角色及状态限制：普通成员无法管理员操作，非 OPEN 工单不能编辑/指派。

## 3. 添加成员用邮箱还是编号？

沿用现有后端 user_id 契约，同事先注册，在组织工作台查看账号编号再提供给管理员。没有邀请邮件/邮箱搜索接口，不在前端伪造查询。ID 使用字符串无损保存，提交为 JSON 整数；不使用 Number 转换大整数。

## 4. 组织里所有 member 不都是 user 吗？

是。user 表示身份，member 是该 user 在某个组织中的关系。一个 user 可以在 A 是 admin、在 B 是 member、在 C 没有关系，单独 users 无法表达这些不同权限。JWT 验证身份后还必须查询当前组织关系。

## 5. 409 是失败还是已经保存？

该次旧版本修改没有覆盖最新数据。界面关闭旧表单、刷新并提示重新确认；刷新失败会明确提示。不能直接自动重试，因为用户最初看到的内容已经改变。服务器明确成功但后续刷新失败则要区分写入结果与展示状态，查看最新详情再决定。

## 6. 为什么删工单又要确认？

管理员可以软删工单，页面会隐藏工单和评论，审计信息保留；确认展示标题和 ID，取消不发 DELETE。该 API 没有 expected_version，不能把二次确认说成完整并发版本保护。没有恢复按钮或物理删除功能。

## 7. init 会覆盖我的 DeepSeek 配置吗？

不会。local_setup.py init 只在 .env 不存在时创建，已有文件或符号链接拒绝覆盖。本次实验只在临时目录生成配置，没有修改你的真实 .env。现有机器直接 dev.py 启动即可。

## 8. 源码包为什么没有 node_modules、视频和上传？

源码包保存可审阅代码、依赖锁、迁移及 Markdown；依赖重新安装，私有数据不能分发，原始证据体积大另存主仓库。它是源码交付，不是离线镜像或完整数据备份。逐文件清单与 SHA256 可校验内容，同名文件拒绝覆盖。

## 9. 1181 项全过是否证明没有问题？

不是。它是当前真实 PG/Redis Go race 的 PASS 节点数，含子测试，另有 286 顶层测试、0 Skip。前端、工具及浏览器也分别验证，但测试只能覆盖定义的场景。普通 Go 测试/CI 会 Skip 集成门禁；本地模型 smoke 也不证明真实语义质量。

## 10. 视频是 DeepSeek 真的回答的吗？

本次视频使用本机确定性模型夹具，不收费、不发送私有内容，验证 UI/异步任务/SSE/引用/确认链路。真实 BGE 与 DeepSeek 的评测在 W10 报告，标签人工复核仍待做。两者不能混为同一证据。

## 11. 我以后改代码先看哪里？

从[架构导航](../release/architecture.md)按 main → 注入 → Handler → Service → Repository 找入口，先读相关 API 和测试。改前端查对应 composable 和 client 的作用域；改任务查 token/run/lease 边界。按[维护手册](../release/runbook.md)执行受影响检查。

## 12. 我本人还要做什么？

先按运行指南自己操作，复习[12 个深入问题](../release/interview.md)，独立解释并发领取和任务恢复。再审阅差异决定 Git 提交/公开发布，人工复核评测标签；根据真实掌握程度改[简历素材](../release/resume.md)。个人学习、对外发布与自动开发交付是不同事项。
