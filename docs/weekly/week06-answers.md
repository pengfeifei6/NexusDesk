# 第六周开发问题参考回答

这些是结合本仓库实现整理的参考答案，供后续阅读。实现与回答由 AI 按整周授权完成；不代表你已独立作答。验收事实见 [week06](week06.md)。

1. **为什么切块，为什么重叠？** 长文整体向量容易稀释局部事实，生成上下文也有上限。500 码点窗口定位局部证据，80 码点重叠降低跨边界遗漏，但不能完全避免。比如第一块 `[0,500)`，第二块 `[420,920)`。
2. **byte 和 rune 有什么差别？** UTF-8 汉字通常占多个字节，按字节截断可能破坏编码。rune 是 Unicode 码点，中文/Emoji 不会拆坏 UTF-8；复杂组合字符仍可能由多个 rune 组成。偏移必须以提取后的原文为基准。
3. **为什么不能 TrimSpace 每个片段再保留旧偏移？** 片段内容会与原文子串不一致。本版只跳过全空白窗口，保留其他窗口原文与精确偏移。
4. **为什么固定 Embedding 模型和维度？** 不同模型的坐标空间不一致，相同维度也不能直接比较。数据库是 vector(1024)，模型切换需要新的索引与迁移策略，不能只改环境变量。
5. **向量要校验什么？** 数量、1024 维、所有元素有限、非零。极大的有限 float32 也可能让数据库内部范数累计溢出，因此先用 float64 求范数再归一化。不能只检查数组长度。
6. **为什么 `<=>` 升序？为什么暂不建 HNSW？** `<=>` 是余弦距离，越小越近；本版 score=1-distance。精确搜索给出清晰基线，近似索引可能影响过滤与召回，需规模与查询计划证明其必要性。
7. **文档 READY 为什么不代表能搜到？** READY 只表示正文已提取。还需单独建立索引，且索引 READY、hash/模型/chunker/version 匹配、文档未删除。页面分开显示两种状态。
8. **重复索引如何处理？** 同一父文档行锁序列化领取；INDEXING 返回409；相同版本的 READY 直接复用；FAILED 可重试并递增 index_version。没有按请求 ID 实现完整幂等协议。
9. **为什么模型调用不能包在数据库事务里？** 网络和推理可能耗时数十秒，长期占锁阻碍删除/其他请求。先短事务领取，事务外计算，再短事务核验发布。
10. **插入第几个片段失败会怎样？** 删除旧块、插入全部新块和 READY 同一个事务回滚；不会暴露一部分新片段。失败状态单独回写本次 INDEXING，不覆盖其他版本或已成功状态。
11. **处理中被删除或正文改变怎么办？** 完成事务再检查可见父文档与 source hash/version；已变化就拒绝发布。检索 SQL 也检查当前 hash，旧片段即使保留在表里也不可见。
12. **为何不能只在 Prompt 写“仅本组织”？** Prompt 是给概率模型的文本，不是权限系统。攻击者可以诱导模型；真正边界是可信 actor、数据库 active 成员与每个 JOIN/WHERE 的 org_id。
13. **如何保证来源真实？** 模型只返回被允许的 chunk ID。适配器检查实际发送集合，Service 再映射真实召回行、去重并输出原文偏移/文件名。模型无法直接提供一个新 URL 作为引用。
14. **引用 ID 真实是否表示答案正确？** 不表示。模型可能误读真实片段。引用校验解决来源伪造，事实一致性仍要对照原文检查。评测报告把这两者分开。
15. **没有检索结果如何回答？** 不调用生成模型，固定返回“知识库未检索到足够依据。”和空 sources。检索到无关材料时仍要求模型拒答，并单独测量误检索和拒答率。
16. **Mock 测试与真实评测有什么差别？** 确定性假向量适合测事务、错误与隔离，不能证明中文语义检索有效。真实 BGE 向量和固定语料才用于 Recall/MRR；人工标签待核验必须明确写出。
17. **Recall@5、MRR、P95 怎么读？** 手册的 Recall@5 实际是“至少命中一段”的 Hit@5；另记多证据覆盖率。MRR 为第一条相关证据排名倒数均值。P95 为固定样本的最近秩分位数；20题单次测量不能代表生产 SLA。
18. **模型不可用会影响登录和工单吗？** 不会因为启动时模型探测而阻止 API 启动。新 AI 操作返回安全503/504，已有业务继续运行。RAG_ENABLED=false 也保留索引状态读取。
19. **为什么浏览器和服务端都设超时？** 服务端限制计算/SQL资源，浏览器限制等待体验；浏览器预算略大于服务端以收到可解释错误。切换组织、问题、路由和会话还会取消/丢弃旧响应。
20. **下一周要解决什么？** 同步索引的长等待、取消和进程崩溃遗留 INDEXING，适合引入队列、租约和有上限的重试。不能为了恢复而直接把运行中的状态改成 FAILED 或绕过组织权限。

建议自测：关闭 AI 对话，手写一次 500/80 窗口主循环和含 org_id/软删除/hash/version 的检索 SQL；再对照源码解释差异。人工审核20题证据和个人自测的结果由你填写，当前没有代填“已掌握”。
