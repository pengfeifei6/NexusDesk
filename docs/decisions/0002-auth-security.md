# ADR-0002：W02 认证、短期 JWT 与组织授权

- 日期：2026-11-10；状态：本次受托设计采用，待后续实现验证。
- 决策主体：AI 在开发者明确委托 Day 1 全部任务后，按第二周手册补齐；不冒充开发者个人技术结论。
- 相关：[认证设计](../auth-design.md)、[API 契约](../api/auth-organization.md)、[权限矩阵](../authorization-matrix.md)、[ADR-0001](0001-modular-monolith.md)。

## 1. 背景与约束

第一周只有最小 API、数据库连接和组织表。第二周需要在本机完成七个身份与组织接口，重点学习密码存储、凭据校验、租户权限和创建组织的事务。

沿用模块化单体、Gin、pgx 与 PostgreSQL 17，不新增 Redis 或外部身份服务。真实配置和密钥不进入仓库、日志与 AI 上下文。第一周迁移保持不变，新表通过增量迁移添加。

## 2. 选择与备选方案

| 问题 | 本次采用 | 备选及取舍 |
| --- | --- | --- |
| 密码存储 | Argon2id，使用 alexedwards/argon2id 的小封装 | bcrypt 有旧系统兼容价值，但存在 72 字节边界；直接摘要太快，可逆加密不是本项目的密码存储方案 |
| 凭据形式 | golang-jwt/v5，HS256，15 分钟 Access Token | 服务端 Session 更便于集中撤销，但要管理会话存储与过期；当前按手册选 JWT，接受无即时撤销的限制 |
| 签名方式 | 单体内共享至少 32 字节随机密钥的 HS256 | 非对称签名便于多方验签和隔离签名能力，当前没有该需求，不额外引入密钥体系 |
| 权限来源 | 每次组织请求查组织成员关系 | 全局用户角色无法表达一人多组织；Token 内嵌角色会滞后，不作为授权依据 |
| 注册和建组织 | 分开；建组织与首名管理员同事务 | 注册即创建组织简化表面流程，但把账号和租户绑定；仅靠种子数据难演示真实创建与原子性 |
| 本地防滥用 | 回环地址限制，加密码计算并发门限 | 简单失败计数可进一步减少猜测，但需处理容量、重启与代理；可靠限流列为公开部署前必做，不假装已有分布式防护 |

以上为结合手册的设计判断，不是比较测试的性能结论。Argon2id 的成本选择参照 [OWASP 密码存储建议](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)；库的参数单位与随机盐使用方式见 [argon2id 文档](https://github.com/alexedwards/argon2id)。

## 3. 具体决定

1. 初始散列参数为 19456 KiB、2 次、并行度 1、16 字节盐、32 字节派生值；并发计算最多 2 个，超额 503 AUTH_BUSY。本机基准在 Day 3 记录，不降低安全参数以追求未经说明的速度。
2. 密码有效 UTF-8，15～128 码点且最多 512 字节，不截断、不裁剪。未知邮箱使用同成本 dummy 验证；登录返回统一失败信息。完整规范在认证设计与 API 契约维护。
3. JWT 只允许 HS256；必须验证签名、sub、iss、aud、iat、exp，nbf 出现时也验证。iat/exp 存在、时间关系及最长 900 秒是本项目额外约束，不依赖库的宽松默认值。参见 [golang-jwt 验证选项](https://golang-jwt.github.io/jwt/usage/parse/)。
4. JWT 不携带角色、组织或敏感资料；保护接口还确认用户存在，组织请求查 active 成员。禁用某组织成员不会删除账号，也不撤销其在其他组织的访问资格。
5. 本周角色 admin/member，状态 active/disabled，全部小写；只新增成员，不实现修改角色、恢复、停用或删除。
6. 创建组织使用一个事务写两张表；邮箱唯一索引与成员联合主键处理并发重复。应用预查不能代替约束，外键不能代替授权。
7. 本地七个 API 响应使用安全 DTO 和统一错误，不输出密码、散列、密钥和原始数据库错误；仅登录成功响应允许返回 access_token，其他响应不返回 Token。任何 Token 均不得进入日志或测试快照。认证代码接入时约束监听为回环 IP。

## 4. 与第一周规划的差异

| 第一周设计 | 第二周采用的具体合同 | 后续影响 |
| --- | --- | --- |
| 大写 MEMBER/SUPPORT/ADMIN、ACTIVE/INACTIVE | 小写 admin/member、active/disabled | 当前只有组织表，无旧角色数据要迁移；后续 support 须新增 migration 扩展 CHECK，不能改已执行文件 |
| 成员列表仅管理员 | active 成员均可查看 | 列表仅返回必要公开字段；添加动作仍限 admin |
| 首批组织依赖演示数据 | 登录用户主动创建 | 组织与首名管理员需同事务；已有无成员演示组织不自动认领 |
| 第二周计划角色修改 | 本周仅添加成员 | 最后一名管理员保护、support 变更与工单并发在后续角色管理阶段实现并验证 |
| users 未明确 display_name、email 唯一实现 | display_name 必填；lower(email) 唯一索引 | Day 2 对齐新表字段和数据库唯一冲突映射 |

第一周的工单状态机仍为未来设计，OPEN 等工单状态名本次不改。认证和成员的数据契约优先使用本 ADR 与配套文档；原始手册和第一周历史记录保留，不重写当时事实。

## 5. 接受的限制与重评条件

短期 JWT 无即时注销或服务端撤销，被窃取的 Token 到期前仍可能可用；需要账号撤销策略、多端会话或公开部署时重新评估 Session/撤销表与密钥轮换。

本周不验证邮箱所有权，重复注册返回 409，因而不具备完整账号枚举防护；也未完成常见密码检查或可靠登录频率限制。公开部署须补 HTTPS、限流、防滥用、凭据和会话管理；本周的回环限制与计算门限不能取代这些能力。

HS256 的验签方也能签发 Token；将来出现独立外部验签方时评估非对称签名。Argon2id 会消耗资源，需要实际基准与并发验证后才能说明成本。成员状态的并发修改属于未来事务设计范围，不能凭“每次查库”宣称即时撤权完全正确。
