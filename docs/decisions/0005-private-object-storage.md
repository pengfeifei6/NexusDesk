# ADR-0005：私有本地对象与可核对的失败补偿

- 日期：2026-11-11；状态：W05 已采用。
- 背景：本地单进程知识库需要安全保存小型文档，为 W06 准备正文；不提前引入 S3、队列或全局去重。
- 关联：[入库设计](../knowledge/ingestion-design.md)、[API](../api/knowledge-documents.md)、[安全验收](../testing/knowledge-upload-security.md)。

## 决策

使用 Go 1.26 `os.Root` 限定文件操作范围。默认根目录 `./var/storage`，创建权限 0700、文件 0600，已有根目录对组/其他用户可读写时拒绝启动。拒绝仓库 web 和 .git 内的根目录，并检查符号链接祖先解析后的实际位置。部署者仍须确保没有另一个静态服务器映射自定义根目录，服务账号是唯一写者。

key 来自 crypto/rand，不包含原文件名或组织输入。上传先写独占临时文件、计算长度和 SHA-256、同步文件，然后 `Root.Link(temp,key)` 原子创建目标，目标存在即失败；最终删除临时链接并同步目录。使用硬链接是为了同时满足同文件系统原子发布和不覆盖，而普通覆盖式 Rename 不符合对象碰撞策略。文件需在支持硬链接与目录同步的本地文件系统上运行；不承诺所有网络文件系统语义相同。

原文件与规范化正文分别计算 hash，既保留准确下载内容，也能识别提取版本的结果。hash 不作为授权凭据，本周不按 hash 合并对象；不同组织相同内容仍有独立对象和权限边界。

## 失败记录与维护

| 记录 reason | 含义 | 后续核对 |
| --- | --- | --- |
| delete_failed | 明确失败后的新对象未能清理，或删除同步失败 | 先核对数据库引用和软删保留策略，再决定清理 |
| metadata_outcome_unknown | 提交结果未知 | 必须确认数据库是否已提交；不得直接按“失败上传”删除 |
| temporary_delete_failed | `.upload-*` 临时链接删除/同步失败 | 停止相关写入后核对类型与链接；不递归删除异常目录 |

记录保存在同一私有根目录，格式 `<key>.cleanup.json`（临时 key 以 `.upload-` 开头），仅包含 key、reason、created_at。先写 `.journal-*` 临时文件并同步，关闭后原子替换最终记录再同步目录；中断留下的空/截断记录在重试时被修复。符号链接目标不会被跟随。记录中的 key 仍须按允许格式校验，不能直接作为任意删除命令参数。

本周只记录待核对事项，不启动自动清理器。磁盘不可写/文件系统故障时，journal 也可能失败，此时输出固定日志和内部 key，不打印用户正文、凭据或路径。进程直接崩溃可能留下未记录的 `.upload-*`、`.journal-*` 或孤儿对象，维护时需暂停相关写入、按数据库引用人工核对，不做无条件批量删除。

软删除保留对象和已提取正文。备份必须覆盖数据库与私有存储，并确认一致性；只备份 PostgreSQL 无法恢复原附件。当前不提供恢复 API、保留周期或磁盘配额自动管理。

## 验证与取舍

真实文件测试覆盖 5 MiB 边界、SHA-256、权限、碰撞、路径与符号链接、取消和流读取失败；真实数据库触发器验证 INSERT/COMMIT 明确失败后的补偿。已有损坏 journal 和发布失败重试、临时清理失败记录也有测试；不声称模拟了实际断电或磁盘控制器失效。

参考 Go [Root 文档](https://pkg.go.dev/os#Root)与 OWASP [文件上传指南](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)：根目录约束、允许类型、大小限制和私有存储各自承担不同边界。本地实现已按当前版本编译运行，未来更换对象存储需要重新验证一致性与取消语义。
