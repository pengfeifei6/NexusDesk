# ADR-0006：本地模型与精确检索基线

状态：2026-11-11，按用户整周授权实施；技术选型由 AI 提出并执行，不代表开发者已独立掌握。

W05 已有可信组织成员、私有文件和提取正文，需要建立可核验来源的第一个 RAG 版本。决定复用模块化单体、PostgreSQL 17，追加 pgvector 0.8.7 和迁移 9/10；采用固定 1024 维 BGE-M3 与本机 Qwen3.5:35b。实际运行版本与来源验证见 [环境报告](../reviews/week06-environment.md)。[pgvector 官方说明](https://github.com/pgvector/pgvector)支持精确距离查询，本版不建 HNSW/IVFFlat。

理由：本机已有 Ollama 和可用 GPU；不需要外部密钥或把私有正文传出本机。先固定模型、窗口和精确 SQL，便于解释失败、检查权限及比较检索指标。手册中的 OpenAI/1536 为示例，项目实际统一 1024，不混用维度。

索引状态与正文状态分离，以 source hash + 模型 + chunker + index_version 作为一致性边界；模型调用不持事务，全部片段与 READY 原子发布。仅将模型当作受限文本生成器；SQL 和 Service 强制组织边界，引用只从真实召回行构造。

代价：本地模型首次加载较慢、需要较大显存；同步索引可超时，进程崩溃需要人工调查遗留 INDEXING。精确检索的小语料指标不能证明大规模性能；后续应先测量再选择 ANN。输入预算和输出上限限制资源消耗，但不是精确 Token 计费器。

验证包括：独立迁移 Down/Up、事务故障和并发、20 个固定语义查询、真实生成、浏览器闭环、两轮只读审查。评测标签由 AI 按原文偏移预标注，人工审核待完成；不把预标注当成人工金标准，也不自动提交 Git。
