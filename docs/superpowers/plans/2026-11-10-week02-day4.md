## 范围与接口

- TokenManager：NewTokenManager(TokenConfig) (*TokenManager,error)、Issue(userID int64) (AccessToken,error)、Verify(raw string) (int64,error)。HS256，15 分钟，必需 sub/iss/aud/iat/exp；验证算法、签名、时间关系、规范正 int64 sub、可选 nbf。时间可在包内测试注入，不修改全局时钟。
- TokenConfig 与环境 JWTConfig 分离；Secret 复制保存，JSON 隐藏。issuer/audience 为有效 UTF-8、1..256 字节，Token 解析输入最多 8192 字节；均为本次明确的资源/编码边界。审查证明原4096限制无法容纳合法标签转义后的输出，已放宽到8KiB并加入签发防线与自验证边界用例。
- JWT 配置：JWT_ISSUER、JWT_AUDIENCE、JWT_TTL_MINUTES=15、JWT_SECRET_BASE64（标准 Base64 规范编码、解码≥32字节）。示例只有占位，真实 .env 不读取/修改，测试使用虚构临时值。
- NewLoginService(ctx, CredentialFinder, LoginPasswords, TokenIssuer) (*LoginService,error)：启动时生成同成本 dummy hash；Login(ctx, LoginInput) (AccessToken,error)。错误密码/未知邮箱统一401，输入400、资源忙503、存储/损坏散列/签发错误500。
- LoginHandler 注册 POST /auth/login；共享16KiB、严格字段/Unicode、固定错误和no-store，不日志输出Token。
- 现有八变量测试夹具和烟测补四个临时JWT变量，保持启动校验一致；W1仍固定版本1，W02运行器新增--login模式。
- 不新建迁移，不实现 /me、中间件、组织、刷新/撤销，不生成或记录真实密钥/Token，不操作日常库、Git或部署。

## Review Focus

- JWT 库的默认选项不能代替必需 Claim 检查；错算法、无签名、错密钥、缺 Claim、超长输入和畸形结构都要拒绝，错误不带原始Token。
- NumericDate 仅接受 int64 范围的 JSON 十进制整数，拒绝小数、字符串、null及溢出，避免库截断导致零宽限规则被放宽；不改变全局 TimePrecision。
- 未知邮箱使用每进程一次的 dummy hash；密码验证的布尔结果即使偶然为真也不能让不存在用户登录。
- Context取消、坏散列、DB/签发故障不能变成401或200；登录与注册共享两名额，过载不能无限排队。
- 登录重用 Day 3 的重复字段、未配对代理项、NUL原文与字节上限校验；失败消息不能暴露邮箱是否存在。
- 新配置必须保持旧测试与真实启动可复现，所有真实密钥只由开发者在本地配置；测试材料不归档Token。
