# W02 Day 5 认证中间件与组织事务实施计划

> **For agentic workers:** 使用 superpowers:executing-plans 顺序实施；用户要求全部完成，沿用已有工作区，不重复确认，不自动提交或创建分支。

**Goal:** 完成严格 Bearer 认证、GET /me、创建组织和本人组织列表，证明失败不留下孤立组织。

**Architecture:** RequireUser 验证 Token 后查询用户存在性，仅把 ID 存 Gin Context。组织 Service 校验身份、名称和分页；Repository 用同一 pgx.Tx 创建组织/admin，并提交后返回。复用现有严格 JSON，小接口注入，不新增框架或依赖。

**Tech Stack:** 保留当前 Go/Gin/pgx/Argon2id/JWT 版本、三条迁移与十二变量配置。

**Spec:** [手册 Day 5](../../../项目开发文件/每周开发手册/05_NexusDesk_第二周详细开发手册.md)、[API](../../api/auth-organization.md)、[Repository 契约](../../repository-contracts.md)。

## Global Constraints

- 真实 .env 不读、不改；测试只用隔离临时配置，Token 不进入日志/快照。
- 只增 /me、POST/GET /organizations；成员查询/添加与 RBAC 留 Day 6。
- 认证失败401带 WWW-Authenticate: Bearer，数据库故障500；公开入口保持公开。
- 创建组织只接 name，去首尾空白后1..100码点、有效UTF-8且无NUL；拒绝前端身份/角色字段。
- 列表只接 page/page_size，默认1/20，最大100；拒绝重复/未知/畸形/溢出，过滤active本人关系后按组织ID分页，空数组非null。
- SQL普通上限3秒、事务5秒，回滚使用独立最多3秒清理Context；失败不自动重试，提交不确定性不承诺恰好一次。

## Review Focus

- 重复Authorization、逗号多凭据、空Token、错算法和已删除用户必须拒绝；存储错误不能吞成401。
- Gin Group保护不能意外覆盖公开路由，也不能漏保护组织写入；中间件只存ID。
- 无效UTF/未配对转义、NUL组织名、伪造owner_id必须在写入前拒绝。
- 过滤必须早于分页，disabled和他人组织不可占据当前页；巨大页码不能溢出。
- 第二步/提交/取消失败不能返回201或遗留组织；回滚不能复用已取消Context。

## 决策记录

- Ruling: 保持当前工作区与原生顺序执行 — 用户持续要求直接全部完成且已有未提交W02成果 — 以Day4的38文件清单先核对基线，避免覆盖。
- Ruling: 组织HTTP复用auth的严格字符串JSON入口 — 已有未知/重复字段和Unicode检查，不复制安全解析器 — 小范围包依赖，未来多模块时可再迁移公共HTTP层。
- Ruling: 名称拒绝NUL — PostgreSQL文本不接受该字符，沿用显示名边界 — 合法密码中的NUL仍保持原文。
- Ruling: 使用单个ASCII空格的Bearer格式，scheme大小写不敏感 — 避免宽松解析多凭据 — 非规范空白客户端收到401。
