# W07 design: durable asynchronous document ingestion

User delegated creation and completion of the missing W07 using W06 actual code and W08 manual. Prior full-delegation/no-repeat-confirmation preference persists. Design decisions below are AI implementation choices, not fabricated user decisions. W08 remains reference input, not authorization to implement its SSE/tools/conversations.

## Intent / bridge

W06 has synchronous extraction/indexing and reliable scoped Search/Ask; crashes can leave PROCESSING/INDEXING. W08 explicitly requires independently runnable Redis+Asynq Worker and submit/execute/status for asynchronous indexing. Original 12-week plan also requires parsing, retry, deduplication and crash recovery. Deliver that bridge, preserving existing endpoints and private storage.

Considered: (1) Asynq-only state: simplest but DB commit/enqueue gap and stale-worker publication remain; (2) PostgreSQL jobs as durable intent and business authority, Asynq delivery, bounded repair scanner: selected, one extra table and fencing; (3) general multi-table outbox/event framework: unnecessary at this scale. knowledge_jobs itself is the dispatch intent, not an atomic PostgreSQL+Redis transaction.

## Domain write fencing / compatibility

Introduce internal/platform/taskguard context carrying immutable JobID,OrgID,DocID,RunVersion,ActorID,Token. This package depends on pgx, not knowledge/rag/jobs. All domain mutating transactions lock parent first, then call guard Check to lock/verify job. Async check requires RUNNING exactrun/token, unexpiredlease, currentactiveactor and source; cancel/retry/recovery use same parent→job lock order. Heartbeat only locksjob, never parent.

ClaimProcess and ClaimIndex atomically store task_token with contexttoken. Complete/Fail/Finish must checkguard beforewriting and requirematchingtoken forasync. Sync calls useNULLtoken and cannot claim whiledocument has nonterminalasyncjob. Recovery/cancel/failedcleanup reset PROCESSING/INDEXING only if task_token equals endedattempttoken; clearownership and useexisting allowed safe failurecodes. Stale workers’ independent cleanup must retain guard values via context.WithoutCancel +3s; expired/revoked/canceled contexts cannot overwrite newrun.

Compatibility: old W01–W06 isolated regression DBs stop at earlier migration versions. taskguard can detect to_regclass('public.knowledge_jobs') within boundedtransaction; noasyncguard+absenttable => no-op and old SQL statements (no newcolumnreferences). When newtable exists, synchronousclaimclears/newNULLtoken andchecks pending/runningjob. No unconditional newcolumn references againsthistoricalschema. Allin-flightoldapplicationbinaryprocesses mustrestart beforeusingW07; no claim safeconcurrency witholdW06binary unawareofjobs.

Explicit parent-first order across Submit/Claim/Cancel/Retry/Recovery/domainwrites avoids deadlock. Status reads hide jobs ifparentdeleted; workerdeletion checks markinternalterminal safely without exposing404 data. Cancellation cannot undo completed earlier phase; it only prevents later guardedpublication. Worker detects cancel within5s heartbeat; domainfence enforcesbeforecommit. Legacy unowned PROCESSING/INDEXING from W05/W06crashes is not automatically reset (noownershipproof); returnconflict anddocumentmaintenance boundary, do notclaim recoveryforunownedruns.
