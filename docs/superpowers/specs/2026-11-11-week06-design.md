# W06 RAG baseline design

User delegated the complete week under W05 standards. This design records implementation decisions, not claims of personal mastery. Original manual: 项目开发文件/每周开发手册/09_NexusDesk_第六周详细开发手册.md.

## Scope and decisions

Extend the existing Go/Gin/pgx monolith and Vue app with deterministic rune chunks, one fixed real embedder, pgvector exact search, nonstreaming grounded answers, index status UI and search/ask UI. Keep W01–W05 operational. No Redis/Worker/SSE/tools/automatic tickets, no ANN index, no changing old migrations. Existing member-management/ticket-edit UI gaps are outside this week's request.

Alternatives considered: paid external embedding/chat requires new credentials and private-data consent; hash embeddings cannot establish semantic quality; existing local Ollama supports real models without external data transmission. Choose local Ollama bge-m3:567m (1024 dimensions, official BAAI model card) and existing local qwen3.5:35b generation. Reject cloud model names and non-loopback endpoints in this version. Model/size fixed; future change requires explicit migration/reindex. Real fixtures are original fictional technical documents. Evaluation labels are AI-prepared with exact source spans and provenance, pending human review; do not call them human gold labels.

PostgreSQL remains major17. Test pgvector0.8.7 first in disposable resources. Prepare a reproducible same-major image/override. Before any daily DB migration, create an opaque private backup without reading its content; retain daily volume, no Down, no down-v. If changing the existing runtime needs a secret copy forbidden by AGENTS, deliver safe developer commands rather than access secrets. Work in current checkout on feat/week06-rag-baseline with source snapshot: HEAD lacks uncommitted W04/W05, so a clean worktree would omit required baseline. No commit/push/stage.

## Data and algorithms

Chunk by rune window500, overlap80, max200, version rune-500-80-v1; [start_rune,end_rune), preserve exact substring, no trimming that shifts offsets. Empty/whitespace input, invalid UTF8/NUL, >1MiB or >200 chunks return explicit errors, never partial success. Skip a purely whitespace window while retaining its original offsets for other chunks, assign continuous indexes.

Migrations00009/00010: extension vector plus knowledge_chunks and knowledge_document_indexes. Every child has (org_id,document_id) FK to W05 parent; chunks unique(document_id,chunk_index), vector(1024), content/hash/rune offsets/model/chunker_version/index_version. Index row one per document: INDEXING/READY/FAILED, source hash, model/dim/chunker, version, count, failure_code, timestamps. ABSENT is an API view of no row. No destructive DROP EXTENSION in Down.

Claim inside short transaction: lock visible READY parent and current text, verify text exists, detect same READY hash/model/chunker as reusable (no model call), reject INDEXING409, otherwise create/update INDEXING and increment version. Return exact source snapshot and run version. External calls happen outside DB transaction. Finish locks same visible parent/text/index; verify version+INDEXING and source hash still current; replace all chunks and mark READY atomically. Delete or changed-source wins => no publication. Failure uses independent3s conditional update for that version only; no overwrite READY/deleted. Crash/uncertain claim can leave INDEXING for W07 recovery, no automatic steal.

Exact SQL joins chunks, visible READY parent, text, READY index; all org_id match, current source hash, model/dim/chunker and index_version match; ORDER BY embedding <=> query ASC, chunk_id ASC. No user-built SQL. Return cosine score1-distance (not probability); default minimum score0.40, fixed before evaluating labels, top_k1..10/default5. SQL casts validated finite nonzero vectors as text parameter $n::vector, avoiding a new Go dependency.

## Interfaces and public contract

New module internal/rag consumes knowledge.Chunker and existing knowledge.Service via Access interface (Authorize/Get/Text). knowledge never imports rag, avoiding cycles. llm imports rag model interfaces. Root owns orchestration/config/injection/SQL/handlers/scripts/docs.

Sources are only built from real selected rows: chunk_id, document_id, chunk_index, source_name, score, excerpt, start_rune, end_rune. IDs remain int64 JSON numbers; Vue losslessly decodes chunk_id and index_version.

4 routes under /api/v1/organizations/:orgID/knowledge:
POST documents/:documentID/index (no body/query) returns200 IndexInfo; GET same returns200 IndexInfo including ABSENT; POST search and ask strict JSON {query,top_k?}, no querystring. Query nonempty trimmed, max1000runes/4000UTF8bytes, top_k1..10. All authenticated/active members allowed; nonmember/disabled/crossorg/deleted404, unauth401. Index UPLOADED/FAILED-text409. Usual success data/error envelope.

IndexInfo: document_id,status,index_version,embedding_model,embedding_dimension,chunker_version,source_content_sha256,chunk_count,failure_code,started_at,indexed_at,updated_at; nullable absent timestamps/failure. Search: items,embedding_model,embedding_ms,search_ms. Ask: answer,sources,request_id,insufficient_evidence,embedding_model,generation_model. request_id server randomhex, never credentials.

Error codes: inherited INVALID_REQUEST400/UNAUTHENTICATED401/FORBIDDEN403/NOT_FOUND404/INTERNAL_ERROR500; INDEX_STATE_CONFLICT409, INDEX_SOURCE_CHANGED409; INDEX_CONTENT_INVALID422/INDEX_TOO_MANY_CHUNKS422; EMBEDDING_COUNT_MISMATCH502/EMBEDDING_DIMENSION_MISMATCH502/EMBEDDING_INVALID_VECTOR502; MODEL_INVALID_RESPONSE502/MODEL_UPSTREAM_ERROR502/MODEL_UNAVAILABLE503/MODEL_RATE_LIMITED503/MODEL_TIMEOUT504/INDEX_TIMEOUT504/RAG_BUSY503. Fixed public text only.

RAG sources and query are untrusted JSON data under fixed system instructions. Generator returns structured answer/citation_ids(string IDs)/insufficient_evidence; service accepts only retrieved IDs, deduplicates and constructs sources itself. No evidence => fixed Chinese refusal and no generator call. Invalid IDs or malformed/oversize model answer =>502, no fabricated references. Model-declared insufficiency => fixed refusal/sources[]. Answer and snippets plain text; no HTML, external links or tools. Successful non-insufficient answers require a nonempty trimmed answer and at least one deduplicated valid citation. Recheck active membership and current source visibility/hash/version for ALL retrieved sources (a superset of all generation inputs), not just cited ones, before returning search/ask after slow work; no promise of linearizable revocation after response starts.

## Budgets and operational behavior

Adapter batches up to8 texts, each<=4000bytes, total<=32000; truncate:false, max response2MiB embeddings/64KiB chat, no redirects/proxy, context-aware requests, no retries. Validate count/dim/all floats finite/nonzero norm, upstream model name match. Embedding timeout20s, chat35s, index total60s, search25s, ask60s. Context inherited. Generator options num_ctx16384, num_predict512, temperature0, think:false, stream:false; input evidence max5000runes, answer max4000runes. Full json.Marshal(messages) <=12000UTF8bytes; remove lowest-ranked whole sources until it fits, never truncate question/chunk; validate citations only against selected sources. This is a conservative byte budget with output/special-token reserve, not an exact tokenizer measurement. Bounded in-process model admission (2 concurrent calls, fail503 if busy) is not reliable public abuse throttling.

Config optional defaults: RAG_ENABLED=true, OLLAMA_BASE_URL=http://127.0.0.1:11434, EMBEDDING_MODEL=bge-m3:567m, EMBEDDING_DIM=1024, CHAT_MODEL=qwen3.5:35b, RAG_MIN_SCORE=0.40; disabling leaves APIs safe503 and W05 usable. No secrets required. API startup never pulls models and doesn't require Ollama ready. HTTPwrite75s; frontend opts into70s only for index/ask, Search30s and normal requests15s. Route/org/session cancellation clears loading and metadata is refreshed on errors, not automatic write retries.
