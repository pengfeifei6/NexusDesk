# NexusDesk 项目阶段介绍：第七周完成与 DeepSeek 接入

更新日期：2026-11-11。本文描述当前工作区中已实现的功能，以及已有验收记录支持的开发进度。

**NexusDesk 已形成一个可以在本机运行和演示的组织工单与知识库系统：用户能够登录、创建组织、协作处理工单、上传知识文档、在后台完成解析与索引，再通过 DeepSeek 获取带资料来源的回答。**

当前完成范围是前七周的工程任务，加上后续的 DeepSeek 接入和本机启动配置。第八周的流式对话、工具调用与人工确认已有开发手册，尚未实现。现阶段适合功能演示、学习复盘和继续开发；公开部署、高负载运行及完整管理界面仍需后续完善。

## 四、现在可以完成的业务流程

### 1. 工单协作

用户注册并登录后，创建或选择自己所属的组织，再创建工单。有效成员可以领取未指派的 OPEN 工单；领取后状态仍是 OPEN，需要再点击“开始处理”。受理人或管理员按规则解决工单，管理员可以关闭已解决工单，或将其重新打开为处理中。

主要状态路径为：`OPEN → IN_PROGRESS → RESOLVED → CLOSED`；另允许管理员将 `RESOLVED → IN_PROGRESS`。已关闭工单不支持继续新增评论或重新打开。

工单变更使用版本检查，业务更新和事件记录在同一事务中提交。并发领取不会仅依赖前端隐藏按钮来防止冲突。

### 2. 文档异步处理

在知识库选择 TXT 或 Markdown 文件，点击“上传并异步处理”。API 先保存文件和任务，Worker 随后提取正文、分块并调用本地 BGE-M3 建立向量索引，页面显示任务进度和结果。

提交任务返回 `202` 表示已接受，成功完成以任务状态为准。可重试的失败有自动退避和次数限制；符合权限和状态条件时，也可以手动重试或取消。

任务业务状态保存在 PostgreSQL，Redis 用于投递。Worker 使用租约、心跳和任务所有权检查，处理重复投递以及进程中断后的恢复。第七周之前没有任务标识的旧 PROCESSING/INDEXING 记录，不属于这套自动恢复保证。

### 3. 带来源的知识问答

用户提问后，后端检查当前组织权限，使用本地 BGE-M3 将问题转换为向量，再从 PostgreSQL/pgvector 检索该组织当前有效的文档片段。后端把问题和选出的片段发给 DeepSeek，校验返回格式及引用后展示答案。

当前问答只依据检索到的资料；没有足够依据时会明确提示。它暂不保存多轮对话，也不会因为用户说“帮我建工单”就执行工单创建。

## 五、当前技术结构

| 部分 | 技术或位置 | 职责 |
| --- | --- | --- |
| 浏览器页面 | Vue 3、TypeScript、Router、Pinia；`web/` | 交互、状态展示、调用业务 API |
| HTTP 服务 | Go、Gin；`cmd/api/` | 认证、组织权限、工单、知识库及问答接口 |
| 业务模块 | `internal/auth`、`organization`、`ticket`、`knowledge`、`rag`、`jobs` | 业务规则、事务、授权和任务编排 |
| 后台处理 | `cmd/worker/` | 独立执行文档提取与索引任务 |
| 数据库 | PostgreSQL 与 pgvector | 业务数据、正文、向量、索引及持久任务状态 |
| 队列 | Redis 与 Asynq | 投递和消费文档处理任务 |
| 文件存储 | 本机私有 `var/storage/` | 保存原始上传文件，经鉴权接口访问 |
| 模型适配 | `internal/platform/llm/` | 本地向量生成、Ollama 或 DeepSeek 回答生成 |

项目采用模块化单体，API 和 Worker 是同一代码仓库中的两个独立进程。API 和 Worker 使用同一个数据库和私有存储目录。

11 张业务表按用途分为三组：

- 身份与组织：`users`、`organizations`、`organization_members`。
- 工单：`tickets`、`ticket_comments`、`ticket_events`。
- 知识库与任务：`knowledge_documents`、`knowledge_document_texts`、`knowledge_chunks`、`knowledge_document_indexes`、`knowledge_jobs`。

## 六、DeepSeek 接入完成到什么程度

当前本机配置选择 `CHAT_PROVIDER=deepseek`、`CHAT_MODEL=deepseek-flash`。DeepSeek 负责回答生成，本地 `bge-m3:567m` 继续负责向量化，因此此前建立的知识库索引可以继续使用，运行当前问答不需要预热本地 Qwen。

适配器已经实现官方 HTTPS 调用、响应大小与超时限制、并发限制、错误映射、结构化结果及引用校验。页面根据接口返回展示实际配置的生成模型，而不是固定显示旧模型名。

真实 API Key 保存在 Git 忽略的本地配置中；API 进程按需使用，前端和 Worker 不接收该 Key。实际使用云端问答时，问题和检索出的相关片段会发送到 DeepSeek；文档原文件和向量索引仍保存在本机。

这次接入已通过真实调用和浏览器验证。它证明当前文档问答链路可用，不能据此推断所有问题都能准确回答，语义效果仍需结合业务资料持续评估。

## 八、如何运行并亲自查看

在项目根目录检查状态：

```bash
cd /media/yjz/pzp/Go/projects/NexusDesk
python3 scripts/dev.py status
```

服务未运行时，在项目根目录分别打开三个终端执行：

```bash
# 终端一
python3 scripts/dev.py api

# 终端二
python3 scripts/dev.py worker

# 终端三
python3 scripts/dev.py web
```

这些脚本会自动加载所需配置；直接使用 `go run ./cmd/api` 仍需自行准备环境变量。依赖服务须先就绪，本地向量模型冷启动时可执行 `python3 scripts/dev.py warmup`。

默认地址是前端 `127.0.0.1:5173`、API `127.0.0.1:8080`、PostgreSQL `5432`、专用 Redis `6380`、Ollama `11434`。`/healthz` 是 API 存活检查，不代表模型、队列和全部业务持续健康。

建议用一个组织做如下演示：

1. 注册或登录，创建并选择组织。
2. 创建工单，领取、评论、开始处理、解决，再以管理员身份关闭。
3. 上传一份 TXT/MD 演示资料，选择异步处理，查看正文、任务和索引状态。
4. 在检索问答页提出资料中能回答的问题，核对 DeepSeek 回答及原文来源。

如果页面没有数据，先确认当前组织中是否实际创建了工单或上传了文档。测试库里的演示数据不会自动出现在日常账号下。若浏览器在另一台电脑，应通过 SSH 转发访问服务器的回环服务。

完整启动、停止、远程访问和排错步骤见 [本机运行指南](demo/local-deepseek-run.md)。

## 十、接下来如何维护已有成果

当前最有价值的维护方式，是保留可复现的运行环境和验收基线，再按模块增量修改。

- 修改前检查 Git 差异，按功能整理当前工作；本地存在未提交文件不等于已保存到远程仓库。不要提交真实 `.env`、私有文件或运行日志。
- 数据备份同时覆盖 PostgreSQL 与私有文件目录。Redis 队列不能代替业务备份，日常排错不使用删卷或批量重置任务状态。
- 新增数据结构使用新迁移，当前下一条编号从 `00012` 开始，不改写已有迁移历史。
- 修改接口时同步确认页面入口、错误提示和权限条件；修改任务时同时检查取消、重试、重复执行与恢复行为。
- 文档修改检查链接与事实；业务修改执行相应测试。真实云验收使用 `python3 scripts/deepseek-smoke.py --live`，会调用 DeepSeek 并可能产生 API 费用。

理解代码时，可先从 `cmd/api/main.go` 和 `cmd/worker/main.go` 看依赖如何组合，再依次阅读认证与组织、工单、文档入库、RAG、异步任务。工单重点看事务与状态机；RAG 重点看检索和引用；异步任务重点看持久状态、租约和执行所有权。

当前成果包含 AI 辅助实现、测试和文档整理。工程验收通过与个人独立掌握是两件事；复盘时可以结合 [第七周参考问答](weekly/week07-answers.md) 逐项对照。
