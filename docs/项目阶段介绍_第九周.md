# NexusDesk 第九周阶段介绍

项目已经从“能完成业务流程”走到“为读接口和模型调用增加基础性能与故障控制”。前八周的注册登录、组织隔离、工单生命周期、私有知识库、带引用检索问答、异步处理和受控 AI 会话都保留。

本周没有增加业务页面或业务 API；仍是 39 个业务接口、9 个页面。新增一个缓存版本表和两条迁移后，共有 14 张业务表 + 1 张缓存版本表、14 条迁移。

## 用户能感受到什么

- 反复查看相同工单/知识列表可以命中服务端 Redis；修改后下一次读取使用新版本。
- Redis 暂时中断时，普通列表通过 PostgreSQL 返回；工单创建和文档状态写入不依赖缓存。
- AI 对话发送有组织和用户额度，超限提示等待并保留输入；限流 Redis 不可用时拒绝新生成，已有历史和人工确认仍可用。
- 工单优先级筛选与知识状态筛选调整了查询方式；实测结果、适用条件和原始计划均可复查。

## 现在怎样读代码

1. `cmd/api/main.go`：配置 → PG pool → 共用 Redis client → listCache → Service.WithCache → AI limiter → router。
2. `internal/platform/config/performance.go` 与限流配置：默认值、开关和合法范围；`scripts/dev.py` 控制配置只传给需要的进程。
3. `internal/ticket/service.go` / `internal/knowledge/service.go` 的 List：数据库权限检查是缓存之前的必要步骤。
4. `internal/platform/cache/cache.go`：取版本、构造 key、有界读写、坏值和故障回源。
5. `migrations/00013_cache_revisions.sql`：数据库提交控制版本可见性，自动覆盖 Worker 和 AI 外层事务。
6. `internal/platform/ratelimit` / `internal/ai/handler.go`：计数原子性、429/503 和 SSE 开始前的检查顺序。
7. 两个 repository.List 与 migration14：动态固定谓词、参数值、排序和新增索引。
